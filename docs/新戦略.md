# 新しい戦略（A〜D・予備）

検討の結果残った4つの戦略と、予備の1つを実装したものです。**どれもまだバックテストで手数料・滑り込みの成績を確かめていません。** 既定はすべてペーパートレード（発注しない）です。

| | 戦略 | ファイル | 保有 | 必要なもの |
|---|---|---|---|---|
| A | TOPIX 段階的ウエイト低減の売られすぎの戻り | `topix_rebalance.py` | 数日 | 移行措置銘柄の一覧（JPX） |
| B | 適時開示の採点 → 翌日・後場に買う | `disclosure_score.py` | 数日 | 開示データ（J-Quants TDnet アドオン、または CSV） |
| C | 材料なしで下がった銘柄の短期の戻り | `no_news_reversal.py` | 1〜2週間 | 対象銘柄の一覧、B と同じ開示データ |
| D | 引け前のモメンタム（日経225 先物） | `futures_close_momentum.py` | 当日の引けまで | 先物口座 |
| 予備 | 注目銘柄のオープニングレンジブレイク | `orb.py` | 当日中 | なし |

それぞれ独立したプロセスとして起動します（`run_<ファイル名>.bat` もあります）。

## 共通の仕組み（A・B・C）

A・B・C は複数日持つので、共通部品 `swing.py` の上に作っています。

- **注文**: 引成（引けで買う）・寄成（寄りで売る）・成行（現物）
- **ポジションの保存**: `kabucom/state/<戦略名>/positions_paper.json`（実発注は `positions_live.json`）。止めて再起動しても続きから管理します。ペーパートレードの注文も `paper_orders.json` に保存します
- **終値の履歴**: kabu API は過去の日足を返さないため、毎日引け後に対象銘柄の板から終値・出来高・売買代金を記録します（`price_history.json`）。**A と C は、下落率の判定に必要な日数（既定 10 日・5 日）＋平均の計算に使う 20 日分の記録が貯まるまで、ほとんど買いません。** 使う前から毎日起動しておいてください
- **決済**: `<接頭辞>_HOLD_DAYS` 営業日後の `<接頭辞>_EXIT_AT`（既定 8:50）に寄成で売ります。場中に気づいた場合は成行。任意で損切り・利確%（場中に現在値で判定して成行）
- **安全策**: 保有中・当日に売買した銘柄は買いません（現物の差金決済対策）。1日の新規数・同時保有数に上限があります
- **ペーパーの約定**: 引成は終値、寄成は始値、成行は現在値で全量約定とみなします（実際より楽観的）

共通の設定（`<接頭辞>` は A=`TR`、B=`DS`、C=`CR`）:

```
<接頭辞>_DRY_RUN=true            # false で実発注
<接頭辞>_BUDGET_PER_TRADE=300000 # 1銘柄の予算（未設定なら AVAILABLE_MARGIN）。90%まで使用
<接頭辞>_MAX_POSITIONS=5
<接頭辞>_MAX_NEW_PER_DAY=3
<接頭辞>_HOLD_DAYS=3
<接頭辞>_TAKE_PROFIT_PCT=0       # 0 = 使わない
<接頭辞>_STOP_LOSS_PCT=0
<接頭辞>_EXIT_AT=8:50
<接頭辞>_COLLECT_AT=15:35        # 引け後の処理（終値の記録など）
<接頭辞>_POLL_INTERVAL_SEC=30
<接頭辞>_MIN_PRICE=0
<接頭辞>_MAX_PRICE=0
<接頭辞>_STATE_DIR=              # 状態ファイルの保存先（未設定なら kabucom/state）
KABU_UNREGISTER_EVERY=40         # 多数の板を取るとき、何銘柄ごとに銘柄登録を全解除するか（0 = しない）
```

## A. TOPIX 段階的ウエイト低減の戻り（`topix_rebalance.py`）

TOPIX の見直しで「移行措置銘柄」（2026年10月7日公表、683銘柄）は、2026年10月〜2028年7月の四半期ごと（1・4・7・10月の最終営業日）に、元のウエイトを 12.5% ずつ下げられます。TOPIX 連動ファンドは実施日の引けで値段を気にせず売るので、小型株が下がりすぎたところを引成で買い、数日後に売ります。

1. 実施日の `TR_ENTRY_AT`（既定 15:10）に、対象銘柄のうち次を満たすものを選ぶ
   - `TR_LOOKBACK_DAYS` 営業日で `TR_MIN_DROP_PCT`% 以上下落（`TR_MAX_DROP_PCT`% より下は別の悪材料とみなし除外）
   - 20日平均売買代金が `TR_MIN_AVG_VALUE` 円以上
   - 銘柄リストに `SellShares`（その回の想定売り株数）があれば「平均出来高の何日分か」を計算し、大きい順に優先。`TR_MIN_IMPACT_DAYS` で下限も設定可
2. 引成で買い、`TR_HOLD_DAYS` 営業日後の寄りで売る

**銘柄リスト** `TR_UNIVERSE_FILE`（既定 `kabucom/topix_transition_list.csv`）: JPX の移行措置銘柄の一覧を CSV にしたもの。

```
Code,Name,SellShares
1234,サンプル,150000
```

`SellShares` は任意です。分かる場合は「TOPIX 連動の保有株数 × 12.5%」などで見積もって入れてください。

```
TR_UNIVERSE_FILE=
TR_EVENT_DATES=               # 実施日をカンマ区切りで上書き（未設定なら 1・4・7・10 月の最終営業日を自動計算）
TR_ENTRY_AT=15:10
TR_LOOKBACK_DAYS=10
TR_MIN_DROP_PCT=5
TR_MAX_DROP_PCT=40
TR_MIN_AVG_VALUE=20000000
TR_MIN_IMPACT_DAYS=0
```

```bash
python topix_rebalance.py            # 監視・売買（引け後の終値記録も自動）
python topix_rebalance.py collect    # 終値の記録だけを今すぐ
python topix_rebalance.py dates      # 実施日の一覧
```

注意:
- **実施日は JPX の公表資料で必ず確認してください。** 自動計算は「1・4・7・10月の最終営業日」という前提です（2026-10-30 の第1回は実施済み。次回は 2027-01-29 の見込み）
- 2027年10月の再評価で、基準を満たした銘柄は低減が止まります。対象銘柄の一覧はその都度更新してください
- 683 銘柄の板を順に取るため、判定に約 1〜2 分かかります（API の流量制限 10回/秒に合わせている）

## B. 適時開示の採点（`disclosure_score.py`）

開示を数値で採点し、好材料の銘柄を翌日（昼休みの開示は後場）に買います。採点と保存は `disclosures.py`。

1. 開示を取得・採点して `kabucom/state/disclosures/YYYY-MM-DD.json` に保存
   - **ルール採点**: タイトル（本文があれば本文も）から -3〜+3。例: 上方修正 +2、優待新設 +2、自社株買い +1（発行済株式の 2% 以上なら +2、5% 以上なら +3）、下方修正 -2、公募増資 -2、継続企業の前提 -3。業績予想の修正は本文の増減率で点数を決める
   - **Claude 採点（任意）**: `DS_LLM_ENABLED=true` で、ルールで点が付いた開示と、業績修正・決算などルールでは判断できない開示を Claude に読ませて点数を付け直す。`pip install anthropic` と `ANTHROPIC_API_KEY` が必要。既定のモデルは `claude-opus-5-5`（`DS_LLM_MODEL` で変更可）で、拒否時は API 側で別モデルに切り替える設定（server-side fallback）を有効にしている。決算期は件数が多いので費用に注意
2. 前場（`DS_MORNING_AT`、既定 9:05）: 前営業日 15:30 〜当日 9:00 の開示で、点数が `DS_MIN_SCORE` 以上の銘柄を、次の条件で成行買い
   - 寄り付いている（特別気配でない）
   - 寄りの窓（前日終値比）が `DS_MIN_GAP_PCT`〜`DS_MAX_GAP_PCT`%
   - `DS_REQUIRE_ABOVE_OPEN=true` なら現在値 ≥ 始値
   - 同じ期間に同じ銘柄の悪い開示（`DS_BLOCK_SCORE` 以下）があれば買わない
3. 後場（`DS_AFTERNOON_AT`、既定 12:35）: 11:30〜12:30 の開示について、12:25 時点の価格（前場終値）と比べて同じ判定
4. `DS_HOLD_DAYS` 営業日後の寄りで売る（既定で損切り 5%）

**開示の取得元**:
- `DS_SOURCE=csv`（既定）: `DS_CSV_DIR`（既定 `kabucom/disclosures_csv/`）の `YYYY-MM-DD.csv`（列: `Code,Name,Time,Title[,Body,Url]`）を読む。手で用意するか、別の方法で取得したものを置く
- `DS_SOURCE=jquants`: J-Quants の TDnet アドオン（Light プラン以上 + 月額 11,000円、個人のみ）。**エンドポイント・認証・項目名はまだ確認できていないので、契約後に公式の仕様書を見て次を設定してください**

```
DS_JQ_URL=                  # 一覧のエンドポイント（必須）
DS_JQ_API_KEY=
DS_JQ_AUTH_HEADER=Authorization
DS_JQ_AUTH_PREFIX=Bearer    # x-api-key 形式なら空にする
DS_JQ_DATE_PARAM=date
DS_JQ_LIST_KEY=data
DS_JQ_PAGE_KEY=pagination_key
DS_JQ_FIELDS=code=Code,name=CompanyName,date=Date,time=Time,title=Title,url=Url
```

```
DS_SOURCE=csv
DS_CSV_DIR=
DS_STORE_DIR=               # 採点結果の保存先（C と共用。未設定なら kabucom/state/disclosures）
DS_LLM_ENABLED=false
DS_LLM_MODEL=claude-opus-5-5
DS_LLM_EFFORT=low
DS_MORNING_AT=9:05
DS_SNAPSHOT_AT=12:25
DS_AFTERNOON_AT=12:35
DS_AFTERNOON_ENABLED=true
DS_AFTER_CLOSE_FROM=15:30
DS_MIN_SCORE=2
DS_BLOCK_SCORE=-1
DS_MIN_GAP_PCT=0
DS_MAX_GAP_PCT=10
DS_REQUIRE_ABOVE_OPEN=true
DS_HOLD_DAYS=3
DS_STOP_LOSS_PCT=5
DS_COLLECT_AT=17:30
```

```bash
python disclosure_score.py                     # 監視・売買
python disclosure_score.py fetch 2027-01-28    # 開示の取得・採点だけ（結果を点数順に表示）
```

## C. 材料なしで下がった銘柄の戻り（`no_news_reversal.py`）

日本株は短期で下がった銘柄が戻りやすい（短期リバーサル）と報告されています。悪材料による下落は続きやすいので、**期間内に適時開示が無い**下落銘柄だけを買います。

1. 買う曜日（`CR_WEEKDAYS`、既定 4=金曜）の `CR_ENTRY_AT`（既定 15:10）に、対象銘柄のうち
   - 直近 `CR_LOOKBACK_DAYS` 営業日の騰落率が -`CR_MIN_DROP_PCT`% 以下（-`CR_MAX_DROP_PCT`% より下は除外）
   - 20日平均売買代金が `CR_MIN_AVG_VALUE` 円以上
   - その期間に開示が無い（`CR_EXCLUDE_ANY_DISCLOSURE=false` なら `CR_BLOCK_SCORE` 以下の悪い開示だけ除外）
   を下落率の大きい順に引成で買う
2. `CR_HOLD_DAYS` 営業日後の寄りで売る（既定で損切り 10%）

開示データは B と同じ保存先を使います。`CR_REQUIRE_NEWS_DATA=true`（既定）では、**期間内の開示データが1日でも欠けていれば買いません**（悪材料の下落を誤って買わないため）。`DS_SOURCE` を設定しておけば C も自分で開示を取得します。

**銘柄リスト** `CR_UNIVERSE_FILE`（既定 `kabucom/reversal_universe.csv`）: 列 `Code,Name`。流動性のある銘柄（例: TOPIX500 構成銘柄）を入れてください。

```
CR_UNIVERSE_FILE=
CR_WEEKDAYS=4
CR_ENTRY_AT=15:10
CR_LOOKBACK_DAYS=5
CR_MIN_DROP_PCT=8
CR_MAX_DROP_PCT=30
CR_MIN_AVG_VALUE=100000000
CR_EXCLUDE_ANY_DISCLOSURE=true
CR_BLOCK_SCORE=-1
CR_REQUIRE_NEWS_DATA=true
CR_HOLD_DAYS=5
CR_STOP_LOSS_PCT=10
CR_MAX_NEW_PER_DAY=5
```

```bash
python no_news_reversal.py            # 監視・売買（引け後の終値記録・開示取得も自動）
python no_news_reversal.py collect    # 終値の記録だけを今すぐ
```

## D. 引け前のモメンタム（`futures_close_momentum.py`）

レバレッジ ETF の引けのリバランスなど、値段を気にしない同じ方向の売買で、その日の方向が引けにかけて続きやすいことを狙います。

1. `FM_SIGNAL_AT`（既定 15:00）に日経平均（`FM_INDEX_SYMBOL=101`）の前日比 r を見る
   - |r| ≥ `FM_MIN_MOVE_PCT`%
   - `FM_LETF_EXPOSURES` を設定していれば、想定リバランス額 Σ 純資産額 × L × (L−1) × r が `FM_MIN_REBALANCE_OKU` 億円以上
2. r の方向に先物を成行で新規建て（`FM_LONG_ONLY=true` なら買いのみ）
3. 約定後すぐ、日中立会の引けで返済する引成を出す
4. 建値から `FM_STOP_LOSS_PCT`% 逆行したら引成を取消して成行で返済

```
FM_DRY_RUN=true
FM_FUTURE_CODE=NK225micro     # NK225micro / NK225mini / NK225
FM_DERIV_MONTH=0              # 0 = 直近限月
FM_QTY=1
FM_INDEX_SYMBOL=101
FM_SIGNAL_AT=15:00
FM_ENTRY_DEADLINE=15:30
FM_MIN_MOVE_PCT=0.5
FM_LETF_EXPOSURES=            # 倍率:純資産額(円) をカンマ区切り。例 2:1500000000000,-1:200000000000,-2:150000000000
FM_MIN_REBALANCE_OKU=0
FM_LONG_ONLY=false
FM_STOP_LOSS_PCT=0.7
FM_POLL_INTERVAL_SEC=2
FM_EXCHANGE=23                # 23 = 日中
FM_TIF_MARKET=2               # 成行の TimeInForce（2 = FAK）
FM_TIF_CLOSE=2                # 引成の TimeInForce
FM_SKIP_DATES=                # 見送る日（カンマ区切り）
```

注意:
- **先物の注文の執行条件（成行 = `FrontOrderType` 120、引成 = 18、`TimeInForce`）は kabu ステーション API の仕様書で確認してから実発注してください。** 違っていれば `FM_TIF_*` で合わせます
- 先物は証拠金を超える損失が出ることがあります。ペーパーの約定は成行 = 現在値、引成 = 15:45 以降の現在値です
- レバレッジ ETF の純資産額は自分で調べて設定します（未設定なら前日比だけで判定）

## 予備. オープニングレンジブレイク（`orb.py`）

1. 9:00 + `ORB_RANGE_MINUTES` 分（既定 9:05）に、売買代金急増ランキング（`ORB_RANKING_TYPE=7`）上位 `ORB_RANKING_TOP_N` 銘柄の、寄ってからの高値・安値を記録（`ORB_REQUIRE_BULL=true` なら陽線の銘柄だけ）
2. `ORB_ENTRY_END`（既定 10:30）までに高値を上抜けたら、最良売気配で指値買い（`ORB_FILL_WAIT_SEC` 秒で約定しなければ取消）
3. 損切りはレンジ安値の1ティック下（幅が `ORB_MAX_RISK_PCT`% を超えれば見送り）。利確は損切り幅 × `ORB_TAKE_PROFIT_R` の指値（ストップ高が上限）。`ORB_FORCE_EXIT` に成行で決済

```
ORB_DRY_RUN=true
ORB_BUDGET_PER_TRADE=300000
ORB_RANKING_EXCHANGE=T
ORB_RANKING_TYPE=7
ORB_RANKING_TOP_N=20
ORB_RANGE_MINUTES=5
ORB_REQUIRE_BULL=true
ORB_MAX_RISK_PCT=4
ORB_TAKE_PROFIT_R=5
ORB_MAX_POSITIONS=2
ORB_MAX_ENTRY_ATTEMPTS=2
ORB_FILL_WAIT_SEC=5
ORB_ENTRY_END=10:30
ORB_FORCE_EXIT=15:20
```

保有中・決済の処理は特別買い気配スキャルピングと共通です（利確は指値、損切りはプログラムで監視して成行）。

## 同時に動かすときの注意

- kabu API の情報系の流量制限（10回/秒）は**プロセスごと**に守っているだけなので、たくさん同時に動かすと超えることがあります。A・C の判定時刻（既定 15:10）が重なる場合は、片方の `*_ENTRY_AT` をずらしてください
- 板を大量に取るときの銘柄登録の解除（`KABU_UNREGISTER_EVERY`）は、kabu ステーションの登録銘柄の上限（50）を想定した安全策です。PUSH 配信を使う別のツールを併用している場合は 0 にしてください
- バックテストはまだありません（`backtest/` に後日追加する予定）
