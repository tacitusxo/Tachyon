# Tachyon 運用手順書

このプロジェクトには、独立して動く 3 つの売買ロジックがあります。

| # | ロジック | 起動ファイル | 起動する時間 | 発注 |
|---|---|---|---|---|
| ① | 上方修正監視・自動買い | `main.py` / `run.bat` | 寄り前（9:00 前） | デフォルトはペーパートレード |
| ② | 特別買い気配スキャルピング | `special_quote.py` / `run_special_quote.bat` | 寄り前（9:00 前） | デフォルトはペーパートレード |
| ③ | 前日ストップ高銘柄の押し目買い | `stop_high_rebound.py` / `run_stop_high_rebound.bat` | 寄り前（9:00 前）。引け後の収集のため 15:35 まで動かしておく | デフォルトはペーパートレード |

どのロジックも、**三菱UFJ eスマート証券（旧 auカブコム証券）の「kabuステーション」（Windows のデスクトップアプリ）が起動・ログイン済み**で、その API（`http://localhost:18080`）に接続できることが前提です。Python のプログラムは kabuステーションと**同じ Windows PC** で動かします。

> **⚠️ 同時に複数のロジックを起動しないでください。**
> kabuステーション API はトークンを新しく発行すると古いトークンが無効になります。各ロジックは起動時にトークンを発行するため、2 つ目を起動した時点で 1 つ目は API を呼べなくなります（401 エラー）。1 日に動かすのは 1 つだけにしてください。

---

## 1. 初回セットアップ（最初に 1 回だけ）

### 1-1. 証券口座と kabuステーション

1. 三菱UFJ eスマート証券の口座を開設する
2. kabuステーションを利用できる状態にし（利用条件は eスマート証券のサイトで確認）、PC にインストールする
3. kabuステーションを起動してログインする

### 1-2. kabuステーションの API 設定

1. kabuステーション右上の「システム設定」（歯車アイコン）を開く
2. 「API」タブで **「APIを利用する」にチェック**
3. **本番用の API パスワード**を設定する（ログインパスワードとは別。後で `.env` に書く）
4. ポートが本番用 `18080` であることを確認する（`18081` は検証用。このプロジェクトは `18080` 固定）
5. 設定を保存し、指示があれば kabuステーションを再起動する

### 1-3. Python とプロジェクト

1. Python 3.8 以上をインストールする（インストーラーで「Add Python to PATH」にチェック）
2. このリポジトリを PC に取得する（`git clone` または ZIP ダウンロード）
3. コマンドプロンプトでリポジトリのフォルダに移動し、パッケージをインストールする

   ```bat
   cd C:\path\to\Tachyon
   pip install -r requirements.txt
   ```

### 1-4. 設定ファイル `kabucom\.env`

`kabucom` フォルダの中に `.env` という名前のファイルを作り、以下を書きます（`.env` は Git に含まれません）。

```
# 共通（必須）
KABUCOM_API_PASSWORD=1-2 で設定した本番用APIパスワード
KABUCOM_ACCOUNT_TYPE=4          # 2: 一般口座 / 4: 特定口座 / 12: 法人口座
AVAILABLE_MARGIN=500000         # 1回の買いに使う金額（円）。この 90% まで使う

# ① 上方修正監視
UR_DRY_RUN=true                 # 実発注するときだけ false
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/~~~~   # 検出時の通知先（任意）
MONITORING_INTERVAL_SECONDS=1

# ② 特別買い気配スキャルピング（必要なものだけ。詳細は README）
SQ_DRY_RUN=true                 # 実発注するときだけ false
SQ_BUDGET_PER_TRADE=300000      # 未設定なら AVAILABLE_MARGIN
SQ_MIN_ROOM_PCT=5               # ストップ高までの余地がこれ未満なら見送り

# ③ 前日ストップ高銘柄の押し目買い（必要なものだけ。詳細は README）
SHR_DRY_RUN=true                # 実発注するときだけ false
SHR_BUDGET_PER_TRADE=300000     # 未設定なら AVAILABLE_MARGIN
```

②③のその他の設定項目（利確・損切りの幅、時刻など）は README の各節を参照してください。

### 1-5. 動作確認

kabuステーションにログインした状態で、トークンが取れるか確認します。

```bat
cd C:\path\to\Tachyon\kabucom
python kabu_token.py
```

`トークンの発行に成功しました` と出れば OK です。失敗する場合は「6. トラブルシューティング」を見てください。

## 2. 毎日の準備（共通）

1. **8:45 頃までに kabuステーションを起動してログイン**する
   - 前日から起動しっぱなしでも、ログアウトされていることがあります。必ずログイン状態を確認してください
   - ログアウトするとトークンが無効になり、動いているプログラムも API を呼べなくなります
2. 買付余力が `.env` の金額以上あるか、kabuステーションで確認する
3. その日に動かすロジックを **1 つだけ** 選んで起動する（3〜5 章）
4. 終了後は kabuステーションの注文一覧・約定一覧で、意図しない注文や未決済の建玉が残っていないか確認する

**停止方法（全ロジック共通）**: プログラムを動かしているウィンドウで `Ctrl + C`。注文中・保有中の銘柄があればログに表示されるので、kabuステーションで手動で処理してください（プログラムを止めても、出した注文は取り消されません）。

## 3. ① 上方修正監視・自動買い（`main.py`）

### 何をするか

- 日経の適時開示ページを監視し、タイトルに「上方修正」「増配」「過去最高」を含む発表を見つけたら Slack に通知
- その銘柄を **成行で買う**（金額は `AVAILABLE_MARGIN` の 90% まで、100 株単位）
- ペーパートレード（`UR_DRY_RUN=true`、デフォルト）では発注せず、`[DRY RUN] ○○ を成行で N株 買う想定です` とログに出すだけ
- 監視するのは 9:00〜11:30、12:30〜15:00。時間外は次の取引時間まで待つ

### 手順

1. 「2. 毎日の準備」を済ませる
2. `.env` の `UR_DRY_RUN` を確認する（`true` = ペーパートレード、`false` = 実発注）。**最初はペーパートレードで動かし、どんな銘柄を買うことになるかログで確認してから実発注に切り替えてください**
3. 9:00 前に起動する

   ```bat
   cd C:\path\to\Tachyon\kabucom
   python main.py
   ```

   または `kabucom\run.bat` をダブルクリック
4. `ペーパートレードモードです（発注しません）` または `実発注モードです` と出るので、**モードを必ず確認**
5. `トークンの発行に成功しました` → `上方修正監視を開始します` と出れば監視中
6. 検出されるとログと Slack に出る。実発注モードなら成行で買い注文を出し、ペーパートレードなら買う想定の内容をログに出す

### 注意

- `UR_DRY_RUN` を書いていない場合もペーパートレードになります。実発注したいときは `UR_DRY_RUN=false` を明記してください
- **1 銘柄を買うと（ペーパートレードでは買う想定をログに出すと）プログラムは終了します**。続けて監視したい場合は再度起動してください
- ペーパートレードでも、現在値の取得に kabuステーションへの接続（ログイン）が必要です
- **売りは自動では出ません**。利確・損切りは kabuステーションで手動で行ってください
- 起動直後に表示されている発表は「処理済み」として扱われ、起動後に出た新しい発表だけが対象です

## 4. ② 特別買い気配スキャルピング（`special_quote.py`）

### 何をするか

- 値上がり率ランキング上位から **特別買い気配**（買いが殺到して値が付いていない状態）の銘柄を探す
- ストップ高までの余地が `SQ_MIN_ROOM_PCT` % 未満の銘柄は「出遅れ」として見送る
- 気配より `SQ_MAX_CHASE_PCT` % 上（ストップ高が上限）に**上値指値を 1 回だけ**出し、寄り付いたら寄り値で約定させる（`SQ_ENTRY_MODE=chase` にすると従来どおり気配に追随して出し直す）
- ログに `…のため見送ります` と出た銘柄は、その日は再判定しない
- 約定したら数ティック上で利確の指値売り、数ティック下がったら成行で損切り、15:20 に強制決済

### 手順

1. 「2. 毎日の準備」を済ませる
2. `.env` の `SQ_DRY_RUN` を確認する（`true` = ペーパートレード、`false` = 実発注）。**最初はペーパートレードで数日動かし、ログの損益を確認してから実発注に切り替えてください**
3. 9:00 前に起動する

   ```bat
   cd C:\path\to\Tachyon\kabucom
   python special_quote.py
   ```

   または `kabucom\run_special_quote.bat` をダブルクリック
4. `特別買い気配スキャルピングを開始します（ペーパートレード（発注しません））` のように、**モードが表示されるので必ず確認**
5. 取引時間中（9:00〜11:30、12:30〜15:30）は自動で監視・売買。15:20 の強制決済後、引けたら `Ctrl + C` で停止する

### 注意

- ペーパートレードでは `[DRY RUN]` と付いたログが出て、実際の注文は出ません
- 特別気配中は売買が成立しないため、実際に約定するのはほぼ寄り付いた瞬間です。同値の買い注文が多いと約定しないことが多いです
- 同じ銘柄は 1 日 1 回までしか買いません

## 5. ③ 前日ストップ高銘柄の押し目買い（`stop_high_rebound.py`）

### 何をするか

- **前日の引け後**: ストップ高で引けた銘柄を集めて `kabucom\stop_high_list.json` に保存
- **当日 9:00〜10:00**: その銘柄が寄り後にいったん下がり（デフォルト 3% 以上）、安値から 3 ティック戻したら指値買い
- 約定したら +2% で利確の指値売り、-2% で成行の損切り、15:20 に強制決済

**前日の引け後に銘柄リストを作っておく必要がある**のが他と違う点です。

### 手順（毎日）

1. 「2. 毎日の準備」を済ませる
2. `.env` の `SHR_DRY_RUN` を確認する（最初はペーパートレード推奨）
3. **銘柄リストを用意する**（どちらか）
   - **A. 前日 15:35 までプログラムを動かしていた場合**: 15:35 に自動で収集・保存済みなので何もしなくてよい
   - **B. 前日に動かしていなかった場合**: 当日の **寄り前（9:00 前）** に収集だけを実行する

     ```bat
     cd C:\path\to\Tachyon\kabucom
     python stop_high_rebound.py collect
     ```

     `○○ のストップ高銘柄 N件を保存しました` と出れば OK（○○ は前営業日の日付）。取引時間中は実行できません
4. 9:00 前に起動する

   ```bat
   cd C:\path\to\Tachyon\kabucom
   python stop_high_rebound.py
   ```

   または `kabucom\run_stop_high_rebound.bat` をダブルクリック
5. 起動ログを確認する
   - モード（ペーパートレード / 実発注）
   - `前日ストップ高銘柄 N件を監視します: [...]` → 監視対象。`監視対象の前日ストップ高銘柄はありません` や `日付 … が前営業日 … と一致しません` と出たら、手順 3-B で収集し直してから起動し直す
6. **翌日分の銘柄リストを作るため、15:35 を過ぎるまで動かしておく**。`ストップ高銘柄 N件を保存しました` が出たら `Ctrl + C` で停止してよい
7. 翌朝は 1 からやり直す（トークンの期限切れを避けるため、毎朝起動し直してください）

### 注意

- ストップ高のまま寄らなかった銘柄、下げ幅が 15% を超えた銘柄は買いません
- 10:00 を過ぎると新規の買いはしません（保有中の決済は続けます）
- 同じ銘柄は 1 日 1 回までしか買いません

## 5-2. 新しい戦略 A〜D・予備

ロジックと設定の詳細は [新しい戦略](新戦略.md)。ここでは毎日の動かし方だけを書きます。

### 最初に用意するもの

- A: `kabucom\topix_transition_list.csv`（JPX の移行措置銘柄の一覧。列 `Code,Name[,SellShares]`）
- B・C: 開示データの取得元（`DS_SOURCE`。J-Quants の TDnet アドオンを契約するか、`kabucom\disclosures_csv\` に CSV を置く）
- C: `kabucom\reversal_universe.csv`（対象銘柄の一覧。列 `Code,Name`）
- D: 先物口座

### 毎日の手順

1. 朝 8:40 までに、使う戦略を起動する（`run_topix_rebalance.bat` など。トークンの期限切れを避けるため毎朝起動し直す）
2. **A と C は 15:35 過ぎまで動かしておく**（引け後に終値を記録する。記録が 20 営業日ほど貯まるまでは、ほとんど買わない）
3. B は 17:30 過ぎまで動かしておくと、その日の開示を取り込んでおける（翌朝 9:05 にも取り直す）
4. D は 15:00〜15:45 に動いていれば足りる
5. 保有中のポジションは `kabucom\state\<戦略名>\positions_*.json` に保存されているので、止めて起動し直しても続きから決済します

### 注意

- 既定はすべてペーパートレードです（`*_DRY_RUN=false` で実発注）。**まだバックテストをしていない**ので、しばらくはペーパーで様子を見てください
- D（先物）は、実発注の前に kabu ステーション API の仕様書で先物の注文の条件（成行・引成・TimeInForce）を確認してください
- A の実施日は JPX の資料で確認してください（`python topix_rebalance.py dates` で自動計算の一覧を表示）

## 6. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `トークンの取得に失敗しました` / 接続エラー（`Connection refused` など） | kabuステーションが起動していない・ログインしていない、または API 設定が無効。1-2 を確認し、kabuステーションにログインし直す |
| トークン取得で 401 / パスワードエラー | `.env` の `KABUCOM_API_PASSWORD` が kabuステーションの「本番用」API パスワードと違う |
| 途中から `API エラー … 401` が出続ける | 別のロジックや `kabu_token.py` を起動してトークンが入れ替わった、または kabuステーションがログアウトした。kabuステーションにログインし直し、プログラムを再起動する |
| 発注失敗（余力不足など） | 買付余力が足りない。`AVAILABLE_MARGIN` / `SQ_BUDGET_PER_TRADE` / `SHR_BUDGET_PER_TRADE` を減らすか入金する |
| `Error: KABUCOM_API_PASSWORD environment variable is not set` など | `.env` が `kabucom` フォルダにない、または項目名の書き間違い |
| `ModuleNotFoundError` | `pip install -r requirements.txt` を実行していない |
| `[DRY RUN]` が出て実際の注文が出ない | ペーパートレード中。実発注するなら `UR_DRY_RUN=false` / `SQ_DRY_RUN=false` / `SHR_DRY_RUN=false` |
| 止めたのに注文が残っている | プログラムを止めても注文は取り消されない。kabuステーションで手動で取消・決済する |
